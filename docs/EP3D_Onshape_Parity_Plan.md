## 〇、先解掉一個編號衝突 ✅ 已完成

**現在有兩套 M 編號在跑，而且互相矛盾。**

| 來源 | M17 是什麼 | M18 是什麼 |
|---|---|---|
| repo 實際進度 | 草圖圖元補齊（進行中，已到 M17.30） | 尚未使用 |
| 對齊路線圖 §33.1 | Derived / 跨 Part Studio 重用 | In-context / top-down 設計 |

這正是這個專案反覆出現的那種缺陷——**兩個東西必須一致，各自都對，中間沒人比對**——
只是這次出現在計畫文件上而不是程式碼裡。

### 裁決：repo 編號留下，§33.1 的編號拿掉

理由是**只有一邊焊進了程式碼**：

```text
ADR-M17-054            ADR 編號
M17_SPL_011_...        測試名稱
M17_CLI_025_...        測試名稱
```

這些是永久識別碼，改不得。§33.1 的 M14–M26 只出現在文件裡，
而且它本來就註明「編號僅供規劃」。

**要做的事**：把 §33.1 表格的「階段」欄從 `M14`…`M26` 改成主題名稱
（`Drawing`、`Configurations`、`Surface`…），相依關係欄照舊。
**§52.1 的納入清單同樣要改**，它現在用 M 編號指主題。

這件事本身很小，但不做的話，本文件底下每一個 M 編號都會被讀成兩種意思。

**本文件之後所有 M 編號一律指 repo 進度**，從 M17.30 往下接。

## 一、先說規模，因為這決定計畫長什麼樣

「達到 Onshape」不是一張可以逐項打勾的功能表。誠實的說法是：

**Onshape 是四個各自獨立的產品縫在一起**——Part Studio、Assembly、Drawing、
Configurations——外加一個自訂特徵語言、鈑金、曲面，以及雲端協作。
EP3D 目前完整做出來的是第一個的一部分。

現況的實際數字（M17.30，2026-08-23）：

```text
src + tools     47,307 行
tests           36,440 行
測試            1,458 個（全綠）
文件型別         1 種（Part）
Feature 種類     9 種   Box Pad Pocket Revolve Fillet Chamfer Mirror Pattern Placeholder
草圖約束         22 種
Kernel 操作      13 種  extrude revolve subtract fuse fillet chamfer mirror translate
                        faceQuery tagFaces massProperties createBox
匯入             DXF
匯出             （無）
已有但未成形      ReferenceFrame、Connector（組合件的地基，§33 的 M10 主題）
                MassPropertiesNode（量測的地基，§50 主題）
```

### 各大區塊離「有」還有多遠

| 區塊 | 對齊路線圖主題 | 現況 | 估計規模 |
|---|---|---|---|
| Part Studio — 草圖 | §4、§6、§7 | **接近完整**。22 種約束、15 種工具、橢圓與雲形線都有 | 1 個 milestone 收尾 |
| Part Studio — 特徵 | §11 | 一半。缺掃掠、放樣、薄殼、拔模、孔、環形陣列、布林交集、多實體 | 4 |
| 量測 / 質量性質 | §50 | 有 `MassPropertiesNode`，但**沒有使用者用得到的量測工具** | 0.5，且應提前 |
| 匯入匯出 | §51 | 只有 DXF 進。**沒有 STEP，沒有 STL** | 1 |
| Assembly | §18–§23 | 只有 `ReferenceFrame` 與 `Connector` 骨架 | 4，含一套新的 3D 求解器 |
| Drawing | §24 | **零** | 3 |
| Variables / Configurations | §42、§43、§17 | Parameter 與 Expression 有了，變體沒有 | 2 |
| Derived / In-context | §47、§48 | **零** | 1–2 |
| 鈑金 | §11.2 | **零** | 各自是一個產品 |
| 曲面 | §11.2 | **零** | 各自是一個產品 |
| 自訂特徵機制 | §52.2 | **零** | 語言 + 沙箱，各自是一個產品 |

「milestone」用這個專案自己的尺度：M17 是一個 milestone，底下有 30 個子項，
花掉的程式碼大約是 20,000 行含測試。**這不是週數估計**，是工作量的相對刻度。

照這個刻度，走到「Part Studio + Assembly + Drawing 可用」大約是 **15 個 milestone**，
也就是**目前整個專案規模的三到四倍**。鈑金、曲面、自訂特徵機制不含在內。

我把這件事寫在前面，不是要勸退。§2 的 A07 已經裁決功能求全，
這是排程資訊，不是範圍爭論——**知道總長度才排得出順序**。

## 二、排序原則

沿用升級計畫那一條，再加三條這個規模才需要的：

**P1（沿用）——先做正在擋住別人的東西。**
一個被十件事等待的地基，比十件事本身值錢。

**P2 ——每個區塊結束時，必須能做出一個真實的東西。**
不是「掃掠功能可用」，是「用掃掠做得出一根有把手的管件，存檔、重開、改參數、還是對的」。
沒有這條，進度就只剩下自我報告，而這個專案已經看過太多「沈默的成功」。

**P3 ——第二個文件型別的成本只付一次。**
Assembly 是第二個文件型別。序列化、undo、依賴圖、選取、UI 樹——這五樣都要再長一次。
Drawing 是第三個。**做 Assembly 的時候要把這五樣做成通用的**，
否則 Drawing 會再抄一遍，而抄一遍正是這個專案所有缺陷的來源。

**P4 ——每個 milestone 都要消滅接縫，不能只加功能。**
M17 那一輪的教訓：所有缺陷都是「兩個東西必須一致，而各自的測試都不會發現不一致」。
手段已經驗證過——合併成一個型別、換成 capability、換成工廠、一份 visitor 樣板。
**讓不一致變成不可能，而不是再寫一個測試去抓它。**

## 三、計畫本體

### 區塊 A — 把零件做完（M18–M21）

#### M18 — 草圖收尾與量測

1. ✅ **雲形線端點相切**（ADR-M18-001）。關鍵是一個恆等式：Core 的 Catmull-Rom
   兩端反射，使端點導數**恰好等於弦**，所以不需要新殘差 —— 對線是
   `LinesParallel`，對圓是 `TangentAtPoint`。
   同時發現內插被寫了兩份（實體一份、3D 線框一份），已合併。
2. ✅ **線與橢圓相切**（ADR-M18-002）。`h² = a²nu² + b²nv²`，式子裡沒有觸點。
   圓／弧／雲形線／第二個橢圓仍然拒絕：那些需要把觸點參數解出來，
   而目前沒有約束擁有自己的變數。
3. **部分完成** —— 鏡射 ✅（ADR-M18-003，雲形線可以了，橢圓仍拒絕）；
   **Trim / Split / Offset 仍然拒絕**：
   - 雲形線的 Split 不是「取子點列」，Catmull-Rom 的一段無法用原點列精確表示
   - 偏移一條雲形線或橢圓的結果**不是**同類曲線
   - 這三項要嘛接受近似（產生新的雲形線），要嘛不做。
     **決定：等到有使用者真的需要再做，屆時以「明確標示為近似」的方式做。**
4. ✅ **雲形線切線把手**（ADR-M18-005）。求值器從 Catmull-Rom 換成 Hermite ——
   兩者在預設切向下是同一條曲線，所以沒有把手的雲形線一點也沒變。
   把手的**尖端是一個普通的點變數**，所以每一條會抓點的約束都自動會抓它，
   一條新殘差都不用寫。
   誠實記下的一件事：**把手不會黏在點上** —— 它就是兩個自由度，
   要它在點移動後存活就得約束它。
5. ✅ **量測**（ADR-M18-004）。查詢而非文件物件；自己的單位型別，
   因為 `UnitType` 沒有面積，頂替會印出 `2827.4 mm`；近似值標 `(approx)`。
   已接到 CLI 的 `measure` 命令，所以腳本現在可以**檢查自己蓋出了什麼**。

延後（記入 §52）：control point spline、曲率梳、雲形線增刪點。
增刪點有已知的坑——約束用編號指點，插點會重新編號（ADR-M17-054 第四節）。

#### M19 — 掃掠與放樣 ✅ 完成

- ✅ **掃掠**（ADR-M19-001..003）：斷面一張草圖、路徑另一張。
  兩張是必要的 —— 同一張的話斷面會沿著自己平面內的方向被掃，沒有體積。
  `PlanarPathDefinition` 是自己的型別，因為輪廓承諾封閉而路徑不承諾。
- ✅ **放樣**（ADR-M19-002..003）：多個切面，**順序即形狀**，不可重排。
- **Gate 達成**：`examples/sweep-and-loft.ep3ds` 一根彎管加一座錐塔，
  改路徑會跟著走（M19_FEAT_002），存檔重開仍然對（M19_SER_001..004）。
- 還沒有：導引線、有孔切面的放樣、Frenet 以外的扭轉律、UI 按鈕。

#### M20 — 薄殼、拔模、孔 ✅ 完成

三項都**指名面**，所以三項都建在第 1 階段的 `FaceQuery` 上。
`FaceSelection` 是查詢的**聯集**（ADR-M20-001），跟 `EdgeSelection` 同形。

- ✅ **薄殼**（ADR-M20-002）：OCCT 不會拒絕「沒有開口」也不會拒絕「牆比零件厚」，
  兩者都回傳看起來像成功的東西，所以用**量的**抓 —— 掏空後必須比掏空前輕。
- ✅ **拔模**（ADR-M20-003）：拉出方向就是中性面的法向，角度的正負不可正規化。
- ✅ **孔**（ADR-M20-004）：位置是草圖的**點**，所以可以標註、可以約束。
  深度為零 = 穿透，而穿透是去**問**實體伸到哪裡，不是猜。
- **Gate 達成**：`examples/shell-draft-hole.ep3ds` 一個有拔模、有薄殼、
  有四個安裝孔的外殼件。
- 還沒有：沉頭／埋頭／螺紋、可變厚度薄殼、分模線拔模、UI 按鈕。

#### M21 — 陣列補齊與布林 ✅ 完成

- ✅ **環形陣列**（ADR-M21-004）：軸是 frame 的 +Z，步進是**每一份**不是總掃掠。
- ✅ **曲線陣列**（ADR-M21-005）：沿 M19 那條脊，按**弧長**平均。
  取樣器從 `Profile.cpp` 提升成共用的，不是抄一份。
- ✅ **布林交集**，以及 union / subtract 成為一個具名特徵。
- ✅ **多實體**：一個 Body 裡兩個沒被消耗的特徵就是兩個零件；布林把兩個併成一個。
  這逼出 `consumedSolidIds()` 從單數變複數（ADR-M21-001）——
  單數的話布林只能宣告一半，另一半會留下來被畫兩次。
- **Gate 達成**：`examples/patterns-and-booleans.ep3ds`。
- 草圖陣列仍未做（M17.24 的 Transform 複製涵蓋一部分）。
- **這個 milestone 的最大收穫是一個既有缺陷**：ADR-M8-008 的「只能被消耗一次」
  是靠每個站點手抄一次呼叫執行的，而 M20 與 M21 加的**五個特徵全都漏了**
  （ADR-M21-007）。

**區塊 A 結束時**：EP3D 能做出的零件，跟 Onshape 能做出的零件，差別在鈑金與曲面。

### 區塊 B — 對外通道（M22）✅ 已完成

**STEP 匯入匯出、STL 匯出**（§51 的格式矩陣）。ADR-M22-001..007。

排在這裡的理由：零件模型在 M21 之後才定型，早做要改兩次。
但如果需要提早跟真實世界交換資料，**這個 milestone 可以插到任何位置**——
它跟其他人的依賴最少。

- **Gate**：EP3D 存的 STEP，SolidWorks 或 FreeCAD 開得起來；反過來也一樣

**Gate 的狀態，說清楚。** 自動測到的那一半是完整的：

## 四、每個 milestone 算不算完成

四條，缺一不可。這是把「沈默的成功」擋在門外的機制：

1. **可執行的樣本**。`--selftest` 要有一個樣本從頭走到尾，
   而且 CI 要跑**每一個**樣本，不是預設那一個。
2. **突變測試**。新的殘差、新的查詢、新的求解器路徑，每一條至少殺掉一個突變。
   活下來的突變是測試缺口，要補測試而不是改突變。
3. **沒有新接縫**。任何新的「兩個東西必須一致」，要用單一型別／capability／
   工廠／visitor 樣板收掉。做不到的話，要在 ADR 裡寫明為什麼做不到。
4. **ADR**。決定了什麼、為什麼、放棄了什麼、突變測試結果。

## 五、會殺死這個計畫的四件事

**一、拓樸命名在布林鏈上斷掉。**
`CreatedBy` 依賴 OCCT 的 modelling history，而 history 在布林運算鏈上會斷。
零件內部斷掉只是圓角掉了；**組合件的 mate 依賴零件上的面，斷掉就是整台機器散開**，
而且更難診斷。M21 的多實體布林是這個風險第一次真正受壓的地方。

**二、把 3D 求解器當成 2D 求解器的擴充。**
它不是。2D 解的是點，3D 解的是剛體姿態——旋轉不是向量空間，
高斯牛頓在四元數上要另外處理。M24 如果打算「把現在的求解器加個維度」，會整個重寫。

**三、效能。**
目前每次重算都是全鏈重建，kernel 這一層沒有快取。
單一零件撐得住，**組合件撐不住**。觸發點：單次重算超過 1 秒。
最晚在 M23 之前要有 kernel 層的快取。

**四、第三個文件型別。**
Drawing 是第三次做序列化、undo、依賴圖、選取、UI 樹。
如果 M23 沒有把它們做成通用的，M27 會是一次完整的重抄——
而這個專案所有已知缺陷的形狀，就是「抄了一份」。

## 六、如果要縮範圍，我建議動哪裡

A07 規定「不做」需要理由。以下三項如果要延到最後，理由是充分的，記入 §52 即可：

1. **自訂 feature 機制**。它是一個語言加一個沙箱。
   對 local/offline 的單機 CAD，價值遠低於它的成本。
2. **鈑金**。除非目標使用者做鈑金件，否則它服務的是一個很窄的族群。
3. **曲面**。同上，而且它會把 kernel 抽象層整個撐開。

**我不建議縮的**：STEP 匯入匯出（M22）。
沒有它，EP3D 做出來的東西**出不去**，功能再全都只是自己跟自己說話。

## 七、下一步

**M23–M26：組合件。** 區塊 C，整個計畫最大的一塊，也是最容易低估的一塊。

M22 結束代表 EP3D 不再只跟自己說話了。接下來要付的是第六節裡標成「最大」的那筆帳：
組合件不是「零件的延伸」，而是**第二個文件型別、第二套約束求解器**
（3D、六個自由度、剛體而不是點）**和第二棵樹**。

M21 和 M22 已經先付掉它的兩項前置：
- **多實體**與 `consumedSolidIds()` 的複數化 ——
  組合件裡一個實例被兩個 mate 參照是常態，單數的宣告在那裡會立刻塌掉；
- **`ImportFeature` 那條「存句子不存幾何」的路** ——
  一個組合件實例存的同樣是「那份文件裡的那個零件」，而不是零件的複本。
  那條路的代價（來源不見就大聲失敗、依賴圖上沒有邊）在 M22 已經走過一遍，
  組合件會照著走。
