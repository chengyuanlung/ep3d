# M14 — 尺寸標註的繪製（箭頭、延伸線、標註線）

> 依據：`docs/EP3D_Onshape_Alignment_Roadmap.md` §7、§24.4；owner 要求（2026-08-20）：
> 「dimension 要像 AutoCAD 一樣有箭頭線」
> 前置：M12 的 sketch UI
> 狀態：**已實作**，Debug + Release 各 1097/1097；獨立審查與 owner UI validation **未執行**

---

## 1. 問題

M12 的尺寸「顯示」是一條虛線加一個浮在旁邊的數字。那不是尺寸標註，
那是一條線和一個數字。工程圖的尺寸有固定的組成，缺一個都不成立：

```text
延伸線（extension line）    從被量的點立起，與幾何之間留空隙
標註線（dimension line）    平行於被量的方向，偏移一段距離
箭頭（arrowhead）           在標註線兩端，朝外指
數值                        坐在標註線上，把線挖斷
```

---

## 2. 分工：mm 的歸圖面，px 的歸螢幕

| 元素 | 單位 | 理由 |
|---|---|---|
| 延伸線、標註線、角度弧 | **mm**（隨縮放變化） | 它們是圖面的一部分 |
| 箭頭、文字 | **px**（固定大小） | 它們是**被讀**的，不是被量的 |

箭頭若隨縮放變化，1:10 時會小成一個點、50:1 時會吃掉整個幾何——
而 50:1 正是使用者放大去確認細節的時候。

這個分工決定了 `DimensionArrow` **只帶頂點與方向、不帶大小**：
大小是 widget 的事，而只有 widget 知道 px。其餘一律在 Qt-free 層算完
（ADR-M12-001），所以「一個 100 mm 的長度會得到兩個方向相反的箭頭」是可以被測的。

## 3. 各型別的版面

### 3.1 Linear（Length / Distance）

```text
偏移量   clamp(被量長度 × 0.18, 3 mm, 15 mm)
```

**比例而非固定值**：固定偏移會埋掉一個 8 mm 的特徵，在 400 mm 的件上又顯得飄。
兩端都夾住，所以不會退化。

延伸線與幾何之間留 `offset × 0.12` 的空隙、超出標註線 `offset × 0.18`。
箭頭在標註線兩端**朝外**指——一對朝外的箭頭才讀作「這一段」；
兩個同向的箭頭只是兩個記號。

**偏移的方向**由 `OutwardSideFor` 決定：算出整個 sketch 的粗略形心，
把標註推到**遠離幾何主體**的那一側，而不是壓在圖上。

### 3.2 Radius

一條從圓心到圓周的引線，箭頭在圓周朝外，文字帶 **`R` 前綴**。
沒有前綴的話，一條引線無法說明那個值是半徑還是直徑——而那個誤讀會讓零件差一倍。

### 3.3 Diameter

一條穿過圓心的線，兩端各一個朝外的箭頭，文字在圓心把線挖斷（工程圖慣例）。

**整圓的直徑線是水平的**，弧則沿弧的中角。理由：同一個圓若同時標了半徑（45°）與
直徑，兩者會交叉而不是疊在一起；而水平的數值比較好讀。

### 3.4 Angular

繞**兩線的交點**掃一段弧，半徑 = `clamp(較短邊長 × 0.4, 2 mm, 40 mm)`，
兩端箭頭與弧相切，數值放在角平分線上、距離頂點 `半徑 × 1.55`。

- **角度值永遠正立**，不隨弧旋轉——跟著弧轉的角度值在圖上極難讀。
- **兩線平行時退化成只顯示數值**：平行線交於無窮遠，
  隨便挑一個半徑畫一段弧比不畫更糟。

## 4. 兩個只有截圖才看得到的缺陷

這兩個都是在**看了畫面之後**才發現的，而且每一個座標在幾何測試裡都是對的：

1. **角度標註把自己的弧擦掉了**。數值原本放在 `半徑 × 1.18`，正好壓在弧上，
   而數值是「挖背景」繪製的——於是弧被自己的標註擦掉，只剩數字。移到 1.55 解決。
2. **約束圖示與尺寸數值搶同一個位置**。`ResolveElementPoint` 給線的是**中點**，
   而尺寸數值也放在中點，所以每一條被標註的線都會把數字和 H/V/o 徽章疊在一起。
   圖示改錨在**四分之一點**。

這是 M6.14 的同一課再走一次：模型全對、螢幕不對。
因此 widget 現在除了 `paintedDimensions()` 之外，另外數 **`paintedDimensionArrows()`
與 `paintedDimensionArcs()`**——「畫了一個尺寸」和「把它畫成一個尺寸」是兩件事，
前者在一個只印數字的版本裡也會成立。

## 5. `--screenshot`

`--selftest --sample m12-sketch --screenshot <path>` 會把畫布存成 PNG。

加這個旗標的理由很直接：**尺寸繪製的對錯是一個判斷**。
幾何測試能斷言箭頭存在且方向正確，卻無法說出結果讀起來像不像一張圖。
上面那兩個缺陷就是這樣抓到的。

未知旗標仍然必須失敗——`--screenshot` 已加入既有的合法旗標清單。

## 7. ADR

- **ADR-M14-001** — 圖面元素用 mm、被讀的元素（箭頭、文字）用 px。
- **ADR-M14-002** — `DimensionArrow` 不帶大小；大小是 widget 的事。
- **ADR-M14-003** — 偏移量與弧半徑按被量的量值等比縮放並夾住上下限。
- **ADR-M14-004** — 文字角度一律收斂到 ±90° 之內；角度標註不旋轉。
- **ADR-M14-005** — 整圓的直徑線水平、半徑線 45°。
- **ADR-M14-006** — 平行線的角度標註退化為只顯示數值，不畫弧。
- **ADR-M14-007** — widget 分別統計畫出的箭頭與弧。

## 8. 沒有做的

1. **標註位置不能用滑鼠拖曳**。偏移量是算出來的，不是使用者放的；
   AutoCAD 可以拖，這裡還不行。這是這一項最明顯的缺口。
2. **標註之間不會互相避讓**：兩個尺寸標在相近的位置仍會重疊。
3. **沒有公差、沒有前後綴、沒有單位符號**（值是純數字加 `R` / `D` / `deg`）。
4. **箭頭放不下時不會自動翻到線外**（AutoCAD 會把箭頭移到延伸線外側）。
5. **弧長、座標式（ordinate）、倒角標註**尚未存在（roadmap §24.4）。
