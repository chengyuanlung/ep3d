# Validation samples

Deterministic samples for user-assisted UI validation, generated by the viewer
rather than committed as document files (permitted by
`docs/M5_UI_User_Assisted_Validation_Guide.md` §2, provided anyone can reproduce
them without the developer modelling by hand).

Run from the repository root after building:

```
build\Debug\ParametricCADViewer.exe --sample <name>
```

| Sample | Geometry | Expected |
|---|---|---|
| `m4-rectangle` | 100 × 50 mm rectangle, Pad 20 mm, aluminium 2700 kg/m³ | Volume 100000 mm³, Mass 0.2700 kg, COM (50, 25, 10) mm |
| `m4-failed-profile` | the same rectangle with one side missing | Pad fails; no solid drawn; mass properties not current |
| `m4-circle-r10` | circle r = 10 mm, Pad 30 mm | Volume 9424.77796 mm³ (π·100·30) |
| `m4-circle-r20` | circle r = 20 mm, Pad 30 mm | Volume 37699.11184 mm³ — exactly 4× `m4-circle-r10` |

Omitting `--sample` gives `m4-rectangle`.

Each sample is also checked automatically against its own analytical value:

```
build\Debug\ParametricCADViewer.exe --selftest --sample <name>
```

exits 0 and prints `SELFTEST OK`, or exits non-zero naming what failed. This is
the `ViewerSmokeTest` CTest entry for the default sample.

## Why these four, and not the guide's A–D

The guide's samples B and C assume under-constrained and conflicting sketch
states, which are M5 concepts; M4 has no constraint solver. Its Test A edits the
sketch Width, which M4's UI does not expose — only the Pad Length Parameter is
editable. Each substitute above exercises the property the original was checking
using something M4 can actually do:

- **A** → `m4-rectangle`, editing Pad Length instead of Width. Same question:
  does a numeric edit reach geometry, mass and the 3D view correctly?
- **B/C** → `m4-failed-profile`. Same question: is a broken state visible with a
  useful reason, and is a stale result ever shown as current?
- **D** → the two circle samples. Same question: does a dimensional change
  produce the analytically correct volume ratio?
